Persona_izeGitHub ↗

상대에 맞게 메시지를 다듬어 주되, 내 말투와 원래 내용은 그대로 두는 서비스

상사에게 보내는 말과 친구에게 보내는 말은 다르지만, 내가 하려던 말까지 바뀌면 안 됩니다. 그래서 "고쳐 쓰되 사실과 의도는 건드리지 않는다"를 가장 먼저 정했습니다. 팀원 셋이 비전공자라 개발은 제가 전부 맡았고, 팀원들은 평가 사례와 루브릭을 CSV로 만들어 PR로 올렸습니다.

  • 검증첨삭 결과는 규칙 검증을 통과해야만 보입니다. 실패하면 한 번 다시 만들고, 그래도 안 되면 원문을 돌려줍니다.
  • 실험어떤 정보를 넣어야 첨삭이 나아지는지 네 조건(없음 / 상대별 페르소나 / 내 과거 표현 검색 pgvector / 대화 맥락 그래프 Neo4j)으로 비교했습니다. 실패를 보고 검증 규칙 두 개를 고친 뒤 문제 사례 3개를 36회 다시 돌려 모두 통과했습니다.
  • 운영Docker Compose + Caddy(HTTPS)로 배포하고 백업·배포 후 점검 스크립트를 만들었습니다. 아이폰 앱(SwiftUI)은 CI에서 빌드합니다.
  • 결정"내용은 바꾸지 마"를 프롬프트에만 맡기지 않고, 규칙 검증을 코드로 두고 통과하지 못하면 원문을 돌려주는 쪽을 골랐습니다. 첨삭이 안 되는 것보다 내 말이 바뀌는 게 더 큰 실패이기 때문입니다.
  • 배운 점통과율보다 실패한 2회를 들여다본 게 더 도움이 됐습니다. 검증 규칙 두 개를 고친 것도 그 두 건에서 나왔습니다.

직구곰GitHub ↗

AliExpress·Amazon 상품을 네이버·쿠팡에 올려 파는 구매대행을 자동화한 프로젝트

구매대행은 상품 하나를 잘못 올리면 바로 손해가 납니다. 마진 계산을 틀리거나 통관이 안 되는 상품, KC 인증 대상 상품을 놓치면 돈이나 법 문제로 이어지기 때문에, 이런 판단은 LLM에 맡기지 않기로 했습니다.

  • 통제소싱부터 통관·인증 필터, 마진 계산, 등록, 발주까지는 일반 코드로 짰고, 사는 순간 적자가 되는 주문은 사람이 승인해야 넘어갑니다. LLM은 상품성 평가, 한글 상세페이지 작성(DeepL 번역 후 다듬기), 고객 문의 응대 세 곳에만 쓰고, 민감한 문의는 사람에게 넘깁니다.
  • 결정전체를 LLM 에이전트에 맡기는 대신, 돈과 법이 걸린 판단은 코드로 두고 LLM은 세 곳에만 썼습니다. 틀리면 바로 손해가 나는 판단은 같은 입력에 같은 결과가 나와야 테스트할 수 있기 때문입니다.
  • 구조상품 출처(AliExpress, Amazon), 판매 채널(네이버, 쿠팡), 저장소를 인터페이스로 분리했습니다. 채널을 추가하거나 SQLite를 PostgreSQL로 바꿔도 나머지 코드는 그대로입니다.
  • 운영API 키가 없어도 mock 모드로 전체 흐름이 돌아가고, 관리자 대시보드(Next.js)에서 승인과 발주를 처리합니다.
  • 배운 점LLM을 어디에 쓸지보다 어디에 쓰지 않을지를 먼저 정하니, 무엇을 테스트해야 하는지가 분명해졌습니다.

CodeSageGitHub ↗

GitHub PR이 올라오면 자동으로 코드 리뷰를 달아 주는 봇

GitHub Webhook은 응답이 늦으면 실패로 처리하는데, PR이 조금만 커도 LLM 호출이 그 시간을 넘깁니다. 그래서 Webhook은 서명만 확인하고 바로 응답하고, 실제 리뷰는 Redis 큐 뒤의 Worker가 따로 처리하도록 나눴습니다.

  • 리뷰새 커밋이 올라오면 바뀐 부분만 다시 봐서, 같은 지적이 반복되지 않고 토큰도 덜 씁니다. 코멘트에서 @codesage를 부르면 해당 diff를 보고 답합니다.
  • 보안GitHub App 설치 토큰을 JWT로 발급받아 캐싱하고, Webhook은 HMAC 서명으로 검증합니다. PR 본문에 숨긴 지시문에 끌려가지 않도록 프롬프트도 막아 뒀습니다.
  • 운영pytest 55개. Docker Compose로 api, worker, redis, postgres를 한 번에 띄웁니다.
  • 결정Webhook 요청 안에서 바로 리뷰하는 대신 Redis 큐와 Worker로 나눴습니다. GitHub이 정한 응답 시간과 LLM이 걸리는 시간을 서로 묶지 않기 위해서입니다.
  • 배운 점외부 서비스와 연동할 때는 기능보다 그쪽의 시간 제한과 재시도 방식을 먼저 확인해야 합니다.
