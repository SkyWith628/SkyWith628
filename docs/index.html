LLM을 실제 서비스에 붙이는
백엔드를 만듭니다

LLM을 썼다는 사실보다, 그 LLM을 어떻게 검증하고 통제했는지가 더 중요하다고 생각합니다. 틀리면 안 되는 결정은 코드로 정하고, LLM의 출력은 검증을 통과해야 내보냅니다.

GitHub 블로그 포트폴리오 (Notion)

일하는 기준

인덕대학교 컴퓨터소프트웨어학과에 다니고 있고, 올해는 학과 학회장을 맡고 있습니다. 주로 Python, FastAPI, PostgreSQL, Redis, Docker를 쓰고, LLM 쪽은 LangGraph와 Claude, Gemini를 씁니다.

통제

돈이나 인증처럼 틀리면 곤란한 결정은 코드로 정합니다. LLM에는 사람이 판단하던 부분만 맡기고, 위험한 건 사람 승인을 거칩니다.

검증

LLM이 낸 결과는 규칙 검사를 통과해야만 사용자에게 나갑니다. 실패하면 다시 만들고, 그래도 안 되면 원문으로 돌아갑니다.

측정

나아졌는지는 감으로 판단하지 않습니다. 조건을 바꿔 가며 반복해서 돌리고 숫자로 확인합니다.

"고쳐 쓰되 사실과 의도는 건드리지 않는다"를 가장 먼저 정했습니다. 팀원 셋이 비전공자라 백엔드, LangGraph 워크플로, 실험 하니스, 배포까지 개발은 전부 맡았습니다.

원문→LLM 첨삭→규칙 검증→통과하면 추천·실패하면 1회 재생성→그래도 실패하면 원문 반환

  • 227화면 테스트

  • 16개 사례를 조건마다 3번씩 돌렸고, 결과를 보고 검증 규칙 두 개를 고쳤습니다.
  • Docker Compose에 Caddy(HTTPS)를 붙여 배포했고, 백업과 배포 후 점검 스크립트를 만들었습니다.

  • PR 본문에 숨긴 지시문에 끌려가지 않도록 프롬프트를 막아 뒀습니다.
